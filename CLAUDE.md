# Vault — Open Directory Video Browser Extension

This file gives Claude Code (or any AI assistant) the project architecture, features, and constraints without needing to be prompted from scratch.

## What This Extension Does
A **Manifest V3 Chrome Extension** that acts as a full-screen, searchable library for three kinds of sources: plain HTTP open directories (FTP/HTTP index pages), Emby/Jellyfin media servers via their REST API, and individual JS-rendered pages (single-page apps, custom galleries) scraped after rendering in a hidden tab.
"Update index" crawls every enabled server concurrently — directory listings via HTML parsing, media servers via their API, rendered pages via `chrome.scripting` DOM extraction — and caches the entries in a local **IndexedDB**. Users then search, filter by category/server, and play or download files.

**Honest scope, not general-purpose web scraping.** The "page" source type (see `background.js`'s rendered-page section) is a best-effort single-page snapshot — it sees one already-rendered view, not a real crawl of hidden routes, logins, or infinite-scroll content. It exists because a plain `fetch()` cannot see JS-rendered content at all, not because it's a substitute for a real crawler.

## Architecture & Files
- **`manifest.json`** — MV3. Permissions: `storage`, `unlimitedStorage`, `tabs`, `scripting` (injects `extractPageMedia` into a hidden tab for the "page" source type), `downloads` (real downloads — the `download` attribute is ignored cross-origin), `declarativeNetRequest`, `declarativeNetRequestWithHostAccess`. Static host permission for `*.circleftp.net`; `optional_host_permissions` for `http://*/*` and `https://*/*` requested on demand when a user adds a server (any type). `options_page` is `settings.html`.
- **`shared.js`** — loaded by every context (`importScripts` in the worker, `<script>` in pages). Holds `DEFAULT_SERVERS`, `DEFAULT_SETTINGS`, extension sets, `getSettings/saveSettings`, `getServers/saveServers`, `normalizeServerUrl`, `serverLabel`, `originPattern`, all IndexedDB helpers (`openDB`, `dbGetAllFiles`, `dbPutFiles`, `dbDeleteStale`, thumbs, meta) and formatting helpers.
- **`background.js`** — service worker.
  - Crawler with **per-host queues and round-robin scheduling** (`takeNext`/`pump`): `perHostConcurrency` (default 6 — Chrome's socket cap per host) and `globalConcurrency` (default 64).
  - **Write backpressure**: `pump()` stops dequeuing new directories once `crawl.writeBacklog` (unflushed IndexedDB batches) hits `MAX_WRITE_BACKLOG` (6), so a fast burst of discovered files can't buffer without limit while the DB catches up. `flushPending` slices `crawl.pending` into `DB_BATCH_SIZE` (2000) chunks rather than writing whatever has accumulated in one transaction — a single huge directory listing must not become one giant write.
  - **Per-host circuit breaker**: `crawl.hostFailStreak` counts consecutive directory failures per host, reset on any success. At `HOST_FAIL_CIRCUIT` (8) the host's remaining queued directories are drained into `failedDirs` (protected, not fetched) instead of retried, so a dead/rate-limited server can't tie up its connection slots for the rest of the run.
  - `fetchText` — AbortController timeout, retries with backoff, content-type sanity check.
  - `parseListing` — regex anchor parser that handles nginx/Apache/IIS listings, decodes entities (bounded/overflow-safe codepoints), prefers the URL's last path segment over (often truncated) link text, extracts size/date best-effort, never follows links outside the server root; `ANCHOR_RE`'s inner-text capture is length-bounded so malformed/unclosed HTML can't force a scan to end-of-document.
  - Batched serial IndexedDB writes (`flushPending`), throttled progress broadcasts (250 ms), checkpoints every 10 s to `chrome.storage.local.crawlState` for **stop/resume**, keep-alive ping every 20 s.
  - Records carry `crawl_id`; on completion `dbDeleteStale` removes entries under the crawled roots that the run did not touch (the DB is never wiped up front, so the UI stays populated). Folders that failed after retries are collected in `crawl.failedDirs` and their subtrees are **protected** from that cleanup — otherwise one timeout would delete a whole subtree.
  - Redirects are followed but the final URL must stay inside the server root; the listing is parsed against the final URL.
  - `startCrawl` claims `crawl.running` synchronously before any `await` so concurrent `UPDATE_INDEX` messages get `busy` instead of leaking timers.
  - Messages: `UPDATE_INDEX {servers?, resume?}`, `STOP_INDEX`, `GET_CRAWL_STATE`, `DISCARD_RESUME`, `SYNC_RULES`, `TEST_SERVER {url}`, `OPEN_BROWSER`. Broadcasts: `CRAWL_START`, `CRAWL_PROGRESS {snapshot}`, `CRAWL_FILES_FOUND {files}`, `CRAWL_COMPLETE`, `CRAWL_STOPPED`.
  - `syncDynamicRules` keeps one declarativeNetRequest rule per configured host (ids 1000+) that sets permissive CORS headers, so `<video crossorigin>` thumbnail capture works on user-added servers.
  - **Non-directory sources (`type: 'emby'` / `type: 'page'`)**: entries with one of these on them (alongside plain `{url, enabled}` directory entries in the same `servers` array) are crawled via `runAuxCrawls()` instead of the directory walk, dispatching per root to `crawlEmbyServer()` or `crawlPageServer()` (see `AUX_CRAWLERS`). Both run concurrently with the directory scheduler. **`crawl.auxActive` is set synchronously in `setupCrawl()`, before `runCrawl()` is even called** — `runCrawl()`'s first `pump()` call happens synchronously inside its `new Promise(...)` executor, i.e. before `runAuxCrawls()` gets a turn to run, so if the count were set inside `runAuxCrawls()` instead, a crawl with *only* aux servers (no directory roots to keep `globalActive` nonzero) would see a false `auxActive === 0` and broadcast `CRAWL_COMPLETE` before any aux crawl actually ran — caught by a simulation that (unlike the mixed-source one) had zero directory roots. Neither type is checkpointed/resumable — re-listing/re-rendering is cheap, so an interruption just restarts that server from scratch next run.
    - **Emby/Jellyfin** (`crawlEmbyServer`, `embyItemToFile`): paginated `GET {base}/emby/Users/{userId}/Items?Recursive=true&...`. `full_url` embeds the item's stable `Id` plus the current `apiKey`, so a token rotation causes a harmless full resync (old rows fail the `crawl_id` check and get cleaned up, not silently duplicated). `parent_url` uses `root.url` (always ends in `/`, see `normalizeEmbyBaseUrl`) as its prefix — episodes share a `#emby/series/{SeriesId}` parent (grouped like a season), movies each get a unique `#emby/item/{Id}` (so the player's folder-playlist query doesn't lump every movie on the server into one playlist). Poster art comes from `/Items/{Id}/Images/Primary` via a `poster_url` field — `browser.js`'s `fillThumb` uses it directly instead of video-frame capture. `EMBY_AUTH` validates the address via unauthenticated `/emby/System/Info/Public`, then either calls `Users/AuthenticateByName` (password) or lists `/Users` to resolve a `userId` from a supplied API key; only the resulting token/userId are persisted, never the password.
    - **Rendered pages** (`crawlPageServer`, `renderAndExtract`, `extractPageMedia`): opens the exact URL (hash/route preserved — see `normalizePageUrl`, unlike the directory/Emby normalizers which strip it) in a hidden `chrome.tabs.create({active:false})` tab, waits for `status:'complete'` plus a settle delay for client-side rendering, injects `extractPageMedia` via `chrome.scripting.executeScript` to scrape `<a href>`/`<video>`/`<audio>` elements from the **rendered** DOM, then closes the tab. `extractPageMedia` runs inside the target page, not the extension — it must stay fully self-contained (no closures over outer variables); it's also the one piece of this feature that can't run in the Node-based test harness (no real DOM), so it only gets a manual sanity check against a hand-rolled fake `document`, not full simulation coverage like everything else here. Scraped media rarely shares a path prefix with the page's own URL, so `parent_url`/the stale-cleanup scope both use `cleanupPrefix` (the page's **origin**, from `toRoot`) instead of the exact page URL — `dbDeleteStale` and `dbDeleteServer` both accept this as an override to the default same-as-`url` prefix. `PAGE_TEST` runs one real render+extract without writing to the index, for the settings-page "Test" button.
- **`browser.html` / `browser.js`** — the library UI. Loads the whole index into memory once (`getAll`), filters/sorts synchronously, paginates. Renders with `<template>` clones and `textContent` only (remote filenames are untrusted — never use `innerHTML` with them). Thumbnail pipeline (`thumbs`): single IntersectionObserver, concurrency-limited queue, IndexedDB blob cache, black-frame retry. Query prefixes: `ext:`, `is:`, `server:`, `is:favorite`. Cards/rows are `role="button"` with Enter/Space activation and roving arrow-key navigation (`attachGridKeyNav`) delegated on the grid/list container; the document-level page-navigation arrow shortcut checks `e.defaultPrevented` so the two don't fight over ArrowLeft/Right.
  - **Advanced filter panel** (`#filterPanel`, `state.filters`): extension multi-select, size range, date range, playable-only — combines with search/category/server. **Active-filter chip bar** (`renderActiveFilterBar`, `#activeFilters`) shows one removable chip per active dimension (search term, category, server, favorites, each filter facet) and is re-rendered from inside `applyFilters()` so it never drifts out of sync with actual state.
  - **Favorites** (`state.favorites`, a `Set` of `full_url`): toggle via the corner `.fav-btn` on grid cards, the inline action-cluster star (both views), or `is:favorite` in search. Backed by the separate `favorites` IndexedDB store (see below) — never stored as a flag on the `files` record.
  - **Search history** (`state.searchHistory`, persisted to `localStorage['vault.searchHistory']`, capped at `SEARCH_HISTORY_MAX`): committed on Enter or on picking a prior entry; the dropdown (`#searchHistory`) opens on focus-while-empty and closes on blur/Escape/outside-click. The blur-close is delayed and re-checks `document.activeElement` before closing, so refocusing the field within that window doesn't flash-close it.
- **`settings.html` / `settings.js`** — three server panels: **Servers** (open directories: add/remove/toggle/test/re-index/import/export/search-filter), **Media Servers** (Emby/Jellyfin: URL + username/password or API key, authenticates via `EMBY_AUTH` before saving), **Rendered Pages** (a single URL, no auth). Adding any of them calls `chrome.permissions.request` for its origin. Each server row shows a status lamp + indexed file count: `fileCounts` (from `dbCountFilesByServerAll`, a single key-cursor pass over the `server_name` index) for the resting state, overridden live by `liveStatus` while a crawl is running (populated from `CRAWL_PROGRESS`/`CRAWL_START` broadcasts via `applyLiveSnapshot`). Neither of these DB reads should be gated behind `HAS_EXT` — they're plain IndexedDB and work in preview mode too; only `chrome.*` calls need that gate. `buildServerRow()` is the shared row layout for all three lists — `renderServers()`/`renderMediaServers()`/`renderPageServers()` each filter `servers` by `type` (`!== 'emby' && !== 'page'` / `=== 'emby'` / `=== 'page'`) and call it with type-specific `testFn`/labels; a row-shape change should usually go through that shared builder rather than forking it. Every add-flow checks uniqueness by `url` alone across *all* types, not just its own — two entries sharing a `url` under different types would both match background.js's per-server re-index filter (`requested.has(s.url)`, a plain string set) and double-crawl it.
- **`player.html` / `player.js`** — in-extension player: folder playlist from the `parent_url` index, auto-next, resume position (localStorage), keyboard shortcuts, codec-failure fallback.
- **`browser.css`** — hand-written design system shared by all pages (tokens in `:root`). "Projection booth" direction: ink-blue surfaces, tungsten-amber accent, Bahnschrift condensed display type, monospace data face.
- **`rules.json`** — static CORS rules for the default hosts.
- **`icons/`** — PNG icons (generated, no source asset).

## Constraints & Rules (Important for AI Assistants)
- **Zero third-party dependencies**: no `package.json`, no `node_modules`, no bundler, no frameworks, no remote fonts. Vanilla JS + plain CSS only. Keep `browser.css` hand-written — do not reintroduce compiled Tailwind.
- **No native messaging**: videos play in `player.html` (or open raw in a tab). Do NOT add `nativeMessaging`.
- **CORS**: the worker's `fetch` is covered by host permissions; DNR rules exist for media/thumbnail loads in pages. User-added hosts need both the optional permission grant and a dynamic rule (`syncDynamicRules`).
- **IndexedDB**: database `video-browser-db`, version **5**. Stores: `files` (keyPath `full_url`; indexes `server_name`, `parent_url`, `category`, `crawl_id`), `thumbs` (keyPath `url`, value has a JPEG `blob`), `meta` (keyPath `key`), `favorites` (keyPath `url`, value `{url, addedAt}`) — kept separate from `files` on purpose, since the crawler's `put()` overwrites that record on every re-index and would silently drop a flag stored on it. Any schema change requires bumping `DB_VERSION` in `shared.js` and handling the upgrade in `openDB`.
- **Safety**: everything that came from a server (filenames, folder names, URLs) is untrusted. Render with `textContent`, validate URLs with `new URL`, and keep `fullUrl.startsWith(rootUrl)` in the parser.
- **`ftp://` is not supported by Chrome**. Users must enter http(s) addresses; `normalizeServerUrl` rejects other schemes.

## Common Tasks
- **Default servers**: `DEFAULT_SERVERS` in `shared.js` (users can override in Settings; stored in `chrome.storage.local.servers`).
- **Crawler tuning**: `DEFAULT_SETTINGS` in `shared.js`; user overrides live in `chrome.storage.local.settings`.
- **Parsing**: `parseListing` / `parseMeta` in `background.js`. Test quickly with Node by stubbing `importScripts` and `chrome` (see git history / scratch tests).
- **Styling**: edit `browser.css`. Tokens are CSS custom properties on `:root`.
- **New message types**: add a handler to the `handlers` map in `background.js` and call `chrome.runtime.sendMessage` from the page.
